# Политика безопасности CryptoCore

CryptoCore — **учебный проект**, не прошедший независимый аудит. Не применяйте его для хранения коммерческих или персональных секретов.

## Сообщения о проблемах

Для потенциальной уязвимости используйте **приватное сообщение владельцу репозитория** либо GitHub Security Advisory (если функция включена). **Не публикуйте** эксплойты и секреты в открытом Issue до согласования исправления.

В сообщении укажите версию, Python, ОС, шаги воспроизведения, ожидаемое и фактическое поведение, входные данные без реальных секретов.

## Известные ограничения

- AES-128, не AES-256; ECB и классические режимы без аутентификации небезопасны против активного изменения данных.
- Нельзя повторять nonce GCM/EtM и IV в потоковых режимах с тем же ключом.
- GHASH и собственные SHA/HMAC/PBKDF2 на Python не дают гарантированной constant-time защиты от побочных каналов.
- Zeroization `bytearray` в CLI — best-effort, копии секретов могут остаться в памяти.
- Ключи могут выводиться в CLI, PBKDF2 — в stdout; не записывайте вывод в общедоступные журналы.
- Основной файл при AES-шифровании считывается целиком в память; ограничения PBKDF2 не заменяют лимит по итерациям.
